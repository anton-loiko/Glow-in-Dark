**Экспорт под Android (Подготовка ключа)**

1. В верхнем меню выбери `Editor` -> `Editor Settings`.
2. В левой колонке прокрути вниз до раздела `Export` и выбери `Android`.
3. Здесь нужно указать три пути (Godot не умеет собирать игры без внешних инструментов от Google и Oracle):
   — `Java SDK Path`: путь к установленному JDK (версии 17).
   — `Android SDK Path`: путь к папке Android SDK.
   — `Debug Keystore`: путь к файлу цифровой подписи `debug.keystore`.

Если у тебя нет `debug.keystore`, открой терминал своей ОС и выполни команду (убедись, что у тебя установлена Java):

```bash
keytool -keyalg RSA -genkeypair -alias androiddebugkey -keypass android -keystore debug.keystore -storepass android -dname "CN=Android Debug,O=Android,C=US" -validity 9999 -deststoretype pkcs12

```

Положи созданный файл в удобное место и укажи путь к нему в поле `Debug Keystore`.

**Почему это работает:** Операционная система Android имеет строгую систему безопасности. Она категорически отказывается устанавливать приложения, у которых нет криптографической подписи автора.
**Что происходит внутри:** Файл `keystore` — это твоя цифровая печать. Во время экспорта Godot возьмет этот файл и математически подпишет финальный архив с игрой. Приставка "Debug" означает, что ключ тестовый, он нужен только для установки на твой личный телефон (для Google Play понадобится другой, Release ключ).
**К чему это приведёт:** Твой смартфон разрешит установку игры, считая её безопасным приложением от разработчика.

**Сборка APK (Android)**

1. В верхнем меню выбери `Project` -> `Export`.
2. В левом списке выбери пресет `Android` (мы добавили его на Шаге 1).
3. В правой части, в разделе `Options`, найди блок `Architectures`.
4. Поставь галочки напротив `arm64-v8a` (для современных 64-битных телефонов) и `armeabi-v7a` (для старых 32-битных).
5. Нажми кнопку `Export Project` внизу окна.
6. Выбери папку для сохранения. Сними галочку `Export With Debug` внизу окна сохранения (чтобы отключить инструменты отладки и повысить FPS на телефоне) и нажми `Save`.

**Почему это работает:** Мы используем заранее скомпилированные "шаблоны экспорта", которые скачали на первом шаге. Это ядро движка Godot, уже переведенное на машинный язык процессоров ARM.
**Что происходит внутри:** Движок берет всю папку `res://` (сцены, скрипты, картинки) и сжимает её в свой собственный архивный формат `.pck`. Затем он берет шаблон движка для Android, склеивает его с твоим архивом `.pck` и упаковывает всё это в формат `.apk`. В самом конце применяется цифровая подпись из `keystore`.
**К чему это приведёт:** На жестком диске появится один файл (например, `LightInTheDark.apk`). Ты можешь скинуть его на свой Android-телефон любым способом, нажать на него и играть.

**Сборка под iOS**

1. В том же окне `Project` -> `Export` выбери пресет `iOS`.
2. В разделе `Options` найди блок `Application`.
3. Обязательно заполни `App Store Team ID` (твой идентификатор разработчика Apple из 10 символов) и `Bundle Identifier` (уникальное имя, например `com.forwardmobile.lightinthedark`).
4. Нажми `Export Project`, создай для игры отдельную пустую папку и нажми `Save`.

**Почему это работает:** Политика Apple запрещает собирать исполняемые файлы iOS (`.ipa`) на операционных системах Windows или Linux. Это полностью закрытая экосистема, требующая macOS.
**Что происходит внутри:** Godot не пытается собрать финальную игру. Вместо этого он работает как транслятор. Он генерирует папку, внутри которой лежит проект для **Xcode** (официальной среды разработки от Apple). В этот проект аккуратно перенесены все твои сцены, ресурсы и настройки.
**К чему это приведёт:** Ты получишь папку с исходниками. Чтобы запустить игру на iPhone, тебе нужно перенести эту папку на компьютер Mac, открыть файл проекта в программе Xcode, подключить iPhone кабелем и нажать `Build` внутри Xcode.

Базовый цикл разработки прототипа завершен. Остановлено. Жду указаний для полировки, рефакторинга или добавления новых фич.

# Build IOS failed

```sh
Project export for platform: ios iOS -
Failed.
•[Xcode Build]: Failed to run xcodebuild with code
```

**Причина падения:**
Консольная программа `xcodebuild` завершила работу с ошибкой. Системные механизмы Apple прервали компиляцию проекта на этапе вызова из Godot.

**Что именно происходит внутри:**
Godot не может напрямую создать готовое приложение для iPhone. Он генерирует исходный код, а затем в фоновом режиме запускает встроенный компилятор macOS (ту самую утилиту `xcodebuild`), чтобы он собрал библиотеки и запаковал игру. Компилятор падает, потому что Apple блокирует консольные вызовы по двум основным причинам:

1. Системная блокировка: не принято лицензионное соглашение Xcode для консоли.
2. Ошибка авторизации (Code Signing): у Godot нет правильных сертификатов разработчика, чтобы математически подписать собранный код.

_Источник (документация Godot):_ [https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html) ("Exporting for iOS is only supported on a Mac computer with Xcode installed... You must provide an App Store Team ID and a Bundle Identifier...").

**Как исправить:**

### Шаг 1. Снятие системной блокировки (Подтверждение лицензии)

1. Открой стандартное приложение `Terminal` (Терминал) на твоем Mac.
2. Выполни команду:

```bash
sudo xcodebuild -license

```

3. Введи пароль от Mac.
4. Нажимай клавишу `Space` (пробел), чтобы прокрутить текст лицензии до конца.
5. Напиши слово `agree` и нажми Enter.

**Почему это работает:** Apple жестко блокирует любую компиляцию кода через сторонние программы (какой является Godot), пока владелец компьютера физически не примет соглашение разработчика в консоли.

---

### Шаг 2. Обход ошибки цифровой подписи (Code Signing)

Если лицензия принята, но ошибка осталась, значит Godot спотыкается о систему Provisioning Profiles от Apple. Мы делегируем эту работу "большому" Xcode.

1. Вернись в Godot: `Project` -> `Export` -> пресет `iOS`.
2. В разделе `Application` полностью **удали** текст из поля `App Store Team ID`.
3. Нажми `Export Project`.
4. Создай пустую папку (например, `ios_source`) и нажми `Save`.
   _Что произойдет:_ Очистив ID команды, мы говорим движку: "Не пытайся подписывать и собирать финальный билд. Просто переведи сцены GDScript в формат проекта Xcode".
5. Открой сгенерированную папку в Finder. Там будет лежать файл проекта (например, `LightInTheDark.xcodeproj`).
6. Дважды кликни по нему. Проект откроется в полноценной программе Xcode.
7. В Xcode в левой колонке кликни на самый верхний синий значок твоего проекта.
8. В центральной области перейди на вкладку `Signing & Capabilities`.
9. Поставь галочку `Automatically manage signing`.
10. В появившемся поле `Team` выбери свой личный Apple ID (или нажми `Add Account`, если его там нет).
11. Подключи iPhone по кабелю к Mac, выбери свой телефон в верхней панели Xcode и нажми большую кнопку `Play` (Build and Run).

**Почему это работает:** Мы убрали из Godot задачу, с которой он справляется хуже всего. Xcode имеет прямой доступ к серверам Apple. При включении "Automatically manage signing" Xcode сам скачивает нужные бесплатные сертификаты, подписывает игру и отправляет её на телефон.

Жду результат. Никакого движения дальше, пока ошибка не исчезнет.
